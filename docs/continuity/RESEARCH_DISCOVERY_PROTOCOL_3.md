# Research discovery protocol 3 — October 30, 2026

Booking discovery now uses a persisted work plan rather than repeated broad provider prompts. This extends the approved AI task roles; it grants no outreach, account or Calendar permissions.

## Operating flow

1. Read retained contacts, coverage and outbox, then acquire the run lease.
2. Call `research-plan` with that run key. It selects a distinct event/location segment, a current date window, an exact retained venue and its missing entertainment-authority fact. Known contacts and rejected requests remain inputs, not new discoveries.
3. Normal ChatGPT or Lucian performs actual targeted web or existing authenticated-browser checks. Collect the URL/query, actual checked time, visible source date or UNKNOWN, observation type and short excerpt. A search summary is not an original-post read.
4. Call `research-dispatch` with actual source packets. Empty packets are rejected before provider dispatch. Saved objectives cannot be replaced with an arbitrary broad sweep. Independent Gwen/Grok and Seth/Gemini analyses run in parallel, with no additional collector reads. Do not dispatch busywork when no useful evidence exists.
5. Normal ChatGPT reads actual job diagnostics and Lucian verifies the source, exact entity, current need, dates, contact scope and driving evidence. An answer or captured page never certifies a job.
6. Save genuine new evidence or a precise coverage gap. Keep unchanged prospects separate from fresh customer requests. Reconcile the run lease with the actual outcome.

## Repetition and quality controls

- Stable run/batch IDs prevent blind duplicate dispatch. Six distinct event/location segments rotate per Central day; exhausted discovery slots do not repeat the same sweep.
- Search variants avoid requiring the exact phrase "Town Missouri" inside a local post. Web and X date operators are separate. New query variants have regression coverage; they are not proof of new leads.
- Job readbacks expose packet count/provenance, collector counts, repeated sources, wrong-entity sources and unresolved verification. No-source answers remain zero verified research.
- Venue tasks address one exact entity. Ownership, marketing and private-event inquiry roles do not automatically establish entertainment purchasing authority.
- Public requests require original post/profile evidence, explicit future date/place, current need and a public contact route. Private-origin Driving remains a separate coordinator check, limited to forty minutes.
- Private routing links and provider-session links are excluded from plan evidence. Dispatch also rejects private-origin text, including encoded forms. The first diagnostic trial exposed a routing-link copy; stored plan data was sanitized and subsequent packets checked. Earlier external submission cannot be represented as retroactively removed.
